# Архитектурное решение по трейсингу

## Мотивация

1. Устранить задержки в цепочке обработки заказов. Трейсинг укажет где чаще всего "падают" заказы.
2. Диагностировать сбои в работе с партнёрами т.к. этот канал становится всё более важным - кол-во заказов от партнёров растёт
3. Оптимизировать производительность при работе операторов с заказами. Трейсинг поможет найти связь между типами или статусами заказов и продолжительностью загрузки списка.

## Предлагаемое решение

Для внедрения телеметрии предлагается использовать OpenTelemetry.

С обновлённой архитектурной схемой можно ознакомиться тут - [Схема с телеметрией](https://drive.google.com/file/d/1iyuSv7e2NA52buVfNiA6eGGVRfQ0lYJd/view?usp=sharing)

* Необходимо установить в облачное окружение Opentelemetry Collector для сбора метрик и трейсов.
* Далее необходимо добавить SDK для отправки данных в коллектор в следующие компоненты:

  * Internet Shop
  * Shop API
  * CRM
  * CRM API
  * MES
  * MES API
    (!) SDK взять для соответствующих технологий с сайта [OpenTelemetry](https://opentelemetry.io/docs/languages/) - потребуются Java, Javascript (Node.js) и .NET.
* Далее необходимо произвести конфигурации согласно документации OpenTelemetry.

## Компромиссы

1. технически непросто и нецелесообразно настраивать трейсинг для RabbitMQ. Вполне можно обойтись базовыми метриками на уровне клиентов, которые его используют.
2. трейсинг в браузере (Internet Shop, CRM UI) осложнён возможными перегрузками страниц, переходами по ссылкам и т.п. - можно легко потерять корреляцию вызовов относящихся к одному и тому же пользовательскому сценарию.
3. несмотря на то что MES был куплен вместе с исходниками, внутри него могут использоваться blackbox компоненты (библиотеки) по работе с 3D моделеями, внутри которых будет проблематично добавить трейсинг. Можно обойтись и без этого.

## Аспекты безопасности

1. Для подключения к OTel Collector использовать mTLS.
2. Для аутентификации и авторизации пользоватеелей внедрить Keycloak.
3. В Jaeger UI и Grafana подключить SSO через Keycloak.
4. В Grafana раздать роли. Сотрудникам, которые могут только смотреть метрики, должны быть роли Viewer только на просмотр.
5. В Prometheus можно подключить SSO через обратный прокси Oauth2-proxy который будет получать токены в Keycloak
6. Доступ в систему получать через создание обращения в команду поддержки с обоснованием получения доступа и согласованием от непосредственного руководителя.
